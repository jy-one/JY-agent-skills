## 策略框架（V3.4 单仓版 ℹ️）

### 核心度量指标

| 指标 | 定义 | 说明 |
|:---|---:|:---|
| **单日涨幅** | `(今收 - 昨收) / 昨收 × 100%` | 比昨日收盘涨了多少（⚠️ 不是日内涨跌幅） |
| 日内涨幅 | `(今收 - 今开) / 今开 × 100%` | **不用这个**，跳空高开的ETF会被误判为"跌" |

### 买入规则
| 条件 | 说明 |
|:---|---:|
| 执行时间 | 每个交易日 **14:30** |
| 选股逻辑 | **两步筛选法**，详见下方流程图 |
| ⚡ 5%上限 | 如果候选ETF的单日涨幅 **>5%**，跳过它，向下选次优板块 |
| 🌡️ 大盘过滤 | 如果**上证指数当日跌幅 ≥1%**，**不开新仓**（但不强制平仓） |
| 持仓上限 | 同时最多 **1只ETF**，全仓出击 |

### 选股流程详解（两步筛选法）

```
                   全市场ETF（约1205只）
                           │
                           ▼
         ┌─────────────────────────────────────┐
         │  第一步：板块聚合（基于全市场维度）    │
         │                                     │
         │  1. 每只ETF按名称匹配关键词→归入板块  │
         │  2. 每板块取单日涨幅最高的ETF为代表   │
         │  3. 按代表涨幅降序排列                │
         │  4. 取TOP 10板块 → 定今日热点方向     │
         └─────────────────────────────────────┘
                           │
                           ▼
         ┌─────────────────────────────────────┐
         │  第二步：从ETF池中选具体标的（22只池）│
         │                                     │
         │  1. 遍历22只精选池中所有ETF           │
         │  2. 只保留属于TOP 10板块的ETF         │
         │  3. 剔除已持仓的ETF                  │
         │  4. 按单日涨幅从高到低排序             │
         │  5. 跳过单日涨幅>5%的                 │
         │  6. 选第1只 → 全仓买入               │
         └─────────────────────────────────────┘
```

**为什么是全市场定方向 + 精选池选标的？**

- 如果只从22只池子里算板块排名，会因为池子太小导致板块代表失真
- 全市场1205只算出来的TOP 10板块才是真实的热点方向
- 但买的时候只在22只池里挑，保证流动性、规模、板块覆盖的平衡
- 举例：2026-05-06当天，芯片板块代表ETF在全市场维度涨幅最高（+6.32%），但22只池子里的芯片ETF涨幅超5%被跳过，最终选了电池ETF（+4.56%）

### 每日14:30执行流程
```
① 拉取全市场涨幅排行 → 按板块聚合 → 展示TOP 10板块
② 输出每个板块涨幅最高的ETF
③ 从TOP 10板块中，推荐涨幅最高的**1只**ETF（单仓全仓）
④ 检查当前持仓 → 标记需要卖出的
⑤ 保存买卖建议到 pending_trade.json（不自动执行！）
⑥ 结果推送到飞书，提示用户回复"确认执行"
```

### 待确认交易机制（V2.0）

扫描脚本**只输出建议，不自动执行交易**。所有买卖操作以 `pending_trade.json` 为中转：

1. **扫描时**：脚本计算推荐买入/卖出的具体参数（含滑点、手续费、数量），写入 `pending_trade.json`，状态为 `pending`
2. **等待确认**：用户在飞书群看到报告后，回复 **"确认执行"**
3. **执行时**：由LLM读取 `pending_trade.json`，按 **先卖出 → 再买入** 的顺序操作，更新 `positions.json`

详细机制参见 `references/pending-trade-workflow.md`

## 回测会计标准

### 三表对齐原则

呈现回测结果时，**所有交易盈亏必须同时展示三个维度**，不能只给单笔PnL%：

| 维度 | 含义 | 计算方式 |
|:---|:---|---:|
| `盈亏%` | 相对买入成本 | `(卖价 - 买价) / 买价 × 100%` |
| `盈利¥` | 实际到手金额 | `卖出净额 - 买入总成本(含手续费)` |
| `对总资金贡献%` | 对初始**1万元**总资金的百分比 | `盈利¥ / 初始资金 × 100%` |

**为什么必须三表对齐：**
- 单笔PnL%容易误导：通信ETF +10%好看，但它只用了¥4,532仓位，对总资金贡献只有+4.44%
- 多笔交易收益率不能简单累加（叠加仓位制下每笔占用的资金量不同）
- 最终总收益率 = `(最终现金 - 初始资金) / 初始资金 × 100%`，这是唯一标准

### 手续费和滑点模型

```python
# 买入
bv = qty * bp                    # 成交金额
buy_comm = max(bv * 0.0005, 5)   # 佣金：万五，最低5元
cost = bv + buy_comm             # 买入总支出

# 卖出  
sell_px = cur * 0.999            # 滑点：卖出价打99.9%（0.1%冲击成本）
val = qty * sell_px              # 卖出金额
sell_comm = max(val * 0.0005, 5) # 佣金：万五，最低5元
cash += val - sell_comm          # 到手现金

# 单笔盈利（真实验算）
profit = val - sell_comm - cost  # 扣完所有成本后的净盈利
```

### 每日资金曲线输出标准

每笔回测必须输出每日资金流水表，格式：

```
  日期        现金       持仓       总资产       累计收益    操作
  ────────── ──────── ──────── ────────── ────────── ──────────────
  2026-04-16   27.59   9917.40    9944.99     -0.55%   卖通信(+444元) 买储能
```

- `现金`: 可用余额
- `持仓`: 持仓市值（按当日收盘价计算）
- `总资产`: 现金+持仓
- `累计收益`: (总资产-初始资金)/初始资金
- `操作`: 买入/卖出摘要，**含盈利金额**（非百分比）

### 回测交易明细表格式标准

用户要求回测明细表输出时必须包含以下列，按此顺序排列，缺一不可：

```
买入日  卖出日  主题  ETF名称  买入价  买入当日涨幅  卖出价  买入金额  卖出金额  持有收益率  卖出原因
```

| 列名 | 含义 | 格式示例 |
|:---|---:|:---:|
| `买入日` | 买入日期 | `2026-04-03` |
| `卖出日` | 卖出日期 | `2026-04-16` |
| `主题` | 板块分类 | `通信` |
| `ETF名称` | 基金全称 | `通信ETF国泰` |
| `买入价` | 买入价格（含滑点×1.001） | `1.104` |
| `买入当日涨幅` | 买入当日的单日涨幅 | `+1.38%` |
| `卖出价` | 卖出价格（含滑点×0.999） | `1.215` |
| `买入金额` | 含手续费的总买入支出 | `¥  9,059` |
| `卖出金额` | 扣手续费后的到手收入 | `¥  9,956` |
| `持有收益率` | (卖出价-买入价)/买入价 | `+10.02%` |
| `卖出原因` | 触发卖出的条件 | `跌2.25%触发卖出` |

**要求：**
- 表头用 `print("  {sep}")` 分隔线包围，使每笔交易独立成行
- 每行前标注 🟢/🔴 符号表示盈亏
- 买入金额和卖出金额必须带 `¥` 符号，右对齐
- 原因必须是**具体数值**（如"跌2.25%触发卖出"），不能只说"触发止损"
- 持仓天数隐含在日期差中，不在表中单独列出
- 3月和4月合并在同一张表，按买入日期排序

## ⚠️ 常见陷阱

### 日内涨幅 ≠ 单日涨幅（最重要的陷阱！）

```
日内涨幅 = (今收 - 今开) / 今开    ← ❌ 之前一直用这个，错的
单日涨幅 = (今收 - 昨收) / 昨收    ← ✅ 正确用法
```

**后果**：如果用日内涨幅，跳空高开然后回落的ETF（如通信ETF）会被判定为"跌"，永远不可能被买入。换成单日涨幅后通信ETF吃到+10%。

**回测时务必确认用的是 `get_daily_change()` 而非 `get_intraday()`。**

### 可用资金计算陷阱（重要！V2.0新增）

当同时有卖出和买入建议时，计算买入可用资金的逻辑是：

```python
# ✅ 正确算法
remaining_cash = max(0, INITIAL_CAPITAL - sell_rec['cost'])  # 初始资金 - 已持仓成本
sell_net = 卖出净得（扣手续费和滑点后的到手现金）
available = remaining_cash + sell_net
```

**不要这样算（❌ 之前犯过的bug）：**
```python
available = INITIAL_CAPITAL + 卖出净得  # ← ❌ 双倍计算！初始资金已经花掉了！
```

**举例说明：**
- 初始资金 ¥10,000
- 买入159796花了 ¥9,951（含手续费）
- ❌ 错误算法：available = 10000 + 卖出的¥9,819 = ¥19,819
- ✅ 正确算法：remaining = 10000 - 9951 = ¥49, available = 49 + 9819 = ¥9,868

### 脚本只出建议不执行交易（V2.0变化）
脚本现在只写 `pending_trade.json`，不做任何`positions.json`的买卖操作。
用户回复"确认执行"时，由LLM读取pending_trade.json并手动更新positions.json。
**每次使用该技能前，先检查 `pending_trade.json` 的状态，避免重复执行或漏执行。**

### 其他陷阱
- 东财K线和腾讯K线字段顺序相反（东财: 开/收/高/低, 腾讯: 收/开/高/低）
- pivot低点判断需要日频数据，不能用周线月线替代
- **数据源策略**：东财clist拿排行+腾讯拿行情，东财被封时自动降级腾讯
- **板块定义是关键**：关键词决定了ETF归入哪个板块，修改关键词直接影响策略行为
- **回测时注意**：固定ETF池 vs 动态选板块，回测逻辑不同
- **盈利集中度高**：80%以上利润来自1~2笔大赚交易，单仓确保全仓押注在正确标的上

### 5%上限跳过大涨日（真实案例）

| 日期 | ETF | 单日涨幅 | 后续走势 |
|:---|:---|---:|:---|
| 2026-04-23 | 通信ETF国泰 | +6.64% | 次日跌3.6%触发卖出 ✓ |

回测证明：**跳过>5%的ETF在4月份没有损失任何正收益**。被跳过的ETF要么次日回调，要么走不远。这个上限策略有效。

### 单仓优于双仓（关键结论）

在V3.4阶段经历了双仓→单仓→动态调仓→单仓的来回验证：

| 版本 | 全期收益 | 笔数 |
|:---|---:|---:|
| V3.4 双仓 | +2.78% | 26笔 |
| **V3.4 单仓** ✅ | **+3.97%** | **11笔** |
| V3.5 动态(涨>1%双仓) | +3.78% | 13笔 |
| V3.6 动态(震荡双仓) | +3.74% | 23笔 |

**根本原因**：A股ETF动量策略的盈利高度集中——80%以上利润来自1~2笔大赚交易。双仓分散资金到次优标的，反而稀释了利润。单仓就是最好的风控。
